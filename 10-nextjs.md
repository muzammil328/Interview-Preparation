# Next.js Interview

---

# What is Next.js?

**Next.js** is a React framework built on top of React that provides additional features like:

* Server-Side Rendering (SSR)
* Static Site Generation (SSG)
* Incremental Static Regeneration (ISR)
* File-based routing
* API routes
* Image optimization
* Automatic code splitting
* TypeScript support
* Built-in CSS support
* Performance and SEO optimization

---

# Difference Between Next.js and React

React is a **UI library** used for building user interfaces.

Next.js is a **full-stack React framework** that provides routing, rendering strategies, optimization, and server-side features.

| Feature       | React JS                     | Next.js                        |
| ------------- | ---------------------------- | ------------------------------ |
| Type          | UI Library                   | React Framework                |
| Rendering     | Mainly Client-Side Rendering | SSR, SSG, ISR, CSR             |
| SEO           | Requires extra setup         | Better SEO support             |
| Routing       | Uses React Router DOM        | Built-in file-based routing    |
| Performance   | Manual optimization          | Automatic optimization         |
| API           | No built-in API routes       | Built-in API routes            |
| Data Fetching | External solutions required  | Built-in data fetching support |

# Main Rendering Patterns in Next.js

Next.js supports multiple rendering strategies.

---

## 1. Server-Side Rendering (SSR)

HTML is generated on the server for **every request** before being sent to the browser.

### Best for:

* Dynamic pages
* Personalized dashboards
* Real-time data

Example:

```text
User Request → Server Generates HTML → Browser Receives Page
```

Benefits:

* Fresh data on every request
* Better SEO
* Faster initial page load

---

## 2. Static Site Generation (SSG)

HTML is generated **once during build time** and reused for all users.

### Best for:

* Blogs
* Documentation websites
* Marketing pages

Example:

```text
Build Time → Generate HTML → Serve Static Page
```

Benefits:

* Very fast
* CDN friendly
* Good SEO

---

## 3. Incremental Static Regeneration (ISR)

ISR allows static pages to be updated in the background after deployment without rebuilding the entire application.

### Best for:

* Product pages
* News websites
* Content websites

Example:

```text
Static Page → User Visits → Background Update → New Version Served
```

---

## 4. Client-Side Rendering (CSR)

Traditional React rendering where the browser downloads JavaScript and renders the UI on the client.

### Best for:

* Highly interactive applications
* User dashboards

Example:

```text
Browser Downloads JS → React Executes → UI Renders
```

# Server Components vs Client Components (App Router)

| Server Component                      | Client Component                  |
| ------------------------------------- | --------------------------------- |
| Runs on the server                    | Runs in the browser               |
| Reduces JavaScript bundle size        | Adds JavaScript to browser bundle |
| Can fetch data directly               | Used for interactive UI           |
| Can access backend resources securely | Uses hooks and browser APIs       |
| Cannot use state or event handlers    | Supports state, events, and hooks |

---

# Server Component

Features:

* Runs only on the server
* Fetches data securely
* Sends rendered HTML to the browser
* Cannot use:

  * `useState`
  * `useEffect`
  * Event handlers

Example:

```tsx
async function UsersPage() {
  const users = await fetch("https://api.example.com/users");

  return <div>{users}</div>;
}
```

---

# Client Component

Used when a component needs:

* User interaction
* Browser APIs
* React hooks
* State management

Example:

```tsx
"use client";

import { useState } from "react";

export default function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      {count}
    </button>
  );
}
```

---

# Passing Data From Server Component to Client Component

Data is passed using **props**.

Example:

```tsx
// Server Component

export default async function Page() {
  const data = await getData();

  return <ClientComponent data={data} />;
}
```

```tsx
// Client Component

"use client";

export default function ClientComponent({ data }) {
  return <div>{data.name}</div>;
}
```

# What Causes Hydration Errors?

Hydration errors occur when the HTML generated on the server does not match the HTML generated by the client browser.

Common causes:

* Using `window` directly
* Using `document` directly
* Using `new Date()`
* Random values during rendering
* Different server and client states

Example:

```javascript
new Date()
```

The server and client may generate different values.

---

# How to Fix Hydration Errors?

Solutions:

### 1. Use `useEffect`

Run client-only code after hydration.

```tsx
useEffect(() => {
  setDate(new Date());
}, []);
```

### 2. Disable SSR for Specific Components

Use dynamic imports:

```tsx
import dynamic from "next/dynamic";

const Component = dynamic(
  () => import("./Component"),
  { ssr: false }
);
```

# File-Based Routing in Next.js

Next.js uses file-based routing.

Files inside the `app` directory automatically become routes.

Example:

```
app/
 ├── page.tsx
 ├── about/
 │    └── page.tsx
 └── products/
      └── page.tsx
```

Routes:

```
/
 /about
 /products
```

No manual router configuration is required.

---

# Dynamic Routes and Catch-All Routes

## Dynamic Routes

Dynamic routes use square brackets.

Example:

```
app/blog/[slug]/page.tsx
```

Routes:

```
/blog/hello-world
/blog/nextjs-guide
```

The value is available as a parameter.

---

## Catch-All Routes

Catch-all routes use three dots.

Example:

```
app/docs/[...slug]/page.tsx
```

Matches:

```
/docs/react
/docs/react/hooks
/docs/react/hooks/use-state
```

The value is received as an array.

# Data Fetching Methods

## getStaticProps (Pages Router)

Fetches data during build time.

Used for:

* Static pages
* Blogs
* Documentation

---

## getServerSideProps (Pages Router)

Fetches data on every request.

Used for:

* Dynamic data
* User-specific pages

---

## generateStaticParams (App Router)

Replacement for `getStaticPaths`.

Generates dynamic routes at build time.

Example:

```tsx
export async function generateStaticParams() {
  return [
    { id: "1" },
    { id: "2" }
  ];
}
```

# Data Fetching Example

```javascript
async function getData() {
  const res = await fetch("API_URL");

  return res.json();
}

const data = await getData();
```

# Automatic Code Splitting

Next.js automatically splits JavaScript bundles.

Benefits:

* Each page loads only required JavaScript
* Faster page loading
* Better performance

---

# next.config.ts

`next.config.ts` is the configuration file for Next.js.

Used for:

* Environment variables
* Image configuration
* Redirects
* Rewrites
* Experimental features

Example:

```ts
const nextConfig = {
  images: {
    domains: ["example.com"]
  }
};

export default nextConfig;
```

# Page Router vs App Router

| Page Router                                    | App Router                                      |
| ---------------------------------------------- | ----------------------------------------------- |
| Older routing system                           | Modern routing system                           |
| Uses `pages` directory                         | Uses `app` directory                            |
| Uses `getServerSideProps` and `getStaticProps` | Uses Server Components and modern data fetching |
| Client components by default                   | Server Components by default                    |
