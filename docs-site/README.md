# Interview Preparation — Docusaurus site

Renders the 22 notes in **`docs-site/notes`** as a browsable site, with working
Mermaid diagrams.

The config points the docs plugin at that folder:

```js
docs: {
  path: './notes',
  routeBasePath: 'notes',
  include: ['**/*.md'],
}
```

## Layout

```
notes/
  01-personal.md … 22-react-machine-coding.md   one file per subject
  node-express/                                 one file per TOPIC
    _category_.json          "Node.js & Express"  (sidebar position 12)
    01-how-nodejs-works.md
    02-what-is-node-js.md
    …
    express/_category_.json "Express.js"
    express/01-what-is-express-js.md …
    rarely-asked/_category_.json "Rarely Asked"
    rarely-asked/01-engines-other-than-v8.md …
```

Every topic file carries its own front matter, so the sidebar order and page
title come from the file itself:

```yaml
---
id: how-nodejs-works            # the URL segment
title: "How Node.js Works (Full Flow)"
sidebar_label: "How Node.js Works (Full Flow)"
sidebar_position: 1
description: "…"
---
```

To split a note the same way later, put each `##` heading in its own file and
give it front matter. Add a new `_category_.json` to create a new sidebar group.

## Commands

```bash
npm install     # first time only
npm start       # dev server with hot reload → http://localhost:3000
npm run build   # production build into build/
npm run serve   # serve the production build locally
npm run clear   # wipe the cache if something looks stale
```

## Useful things to know

- Adding a new note (`notes/23-typescript.md`) needs no config change — the
  sidebar is autogenerated from the files. A new topic inside a group is just a
  new file with `sidebar_position`.
- Mermaid is enabled with `markdown.mermaid: true` in `docusaurus.config.js`.
- If a diagram shows a red syntax error box, run the checker to find it:

  ```bash
  npm run check:mermaid
  ```

  It parses every ```mermaid block in every note and prints the file, block
  number and line of anything broken.
- Broken markdown links are set to `warn` (not `throw`) so one bad link never
  blocks a build. Fix warnings when you see them.
